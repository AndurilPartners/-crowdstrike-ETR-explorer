# CrowdStrike REVEAL Company Explorer

A company explorer built over one governed evidence workbook.

It opens on **Company**, and the first thing it shows is the company, the primary signal,
and one editorial chart. A short headline and a two-sentence deck say what the reading is;
below them a single chart shows spending intent and deployment breadth for the periods the
workbook actually supplies; below that, the story in three moves, the counterpoint, and
what to watch next. The governed research layer — evidence, lineage, KPI bridges, rules,
sources, risks, methodology, claim manifests — is all still here, one click down, and it is
what every sentence above is built from.

The design intent in one line: the reader should encounter the company and the signal
first, the evidence should always be one click away, and the machinery should be powerful
when it is needed and quiet when it is not. There is no mode to switch between those two
states — every view simply is what it is, and the research layer is reached the same way
every time: a link, a drawer, an *Inspect claims* toggle, never a global setting that
changes what the whole application shows.

---

## How to open it

Double-click **`index.html`**. It lands on the Company page.

No server, no npm, no build step, no internet connection. The application runs under
`file://` with plain HTML, CSS and JavaScript. There is no React, no CDN, no external font,
no API and no `fetch()`. Python is used only during the build, to read the workbook. The one
image in the application — the CrowdStrike wordmark — is a local file under `assets/`; it is
never fetched from a remote host, and it fails gracefully (no broken-image icon) if it is
ever moved or removed.

## Files

| File | What it is |
| --- | --- |
| `index.html` | Application shell — header, grouped navigation rail, view containers, drawer, source pane |
| `styles.css` | The screen design system |
| `print.css` | Print styling for the seven named surfaces, loaded `media="print"` |
| `storage-migration.js` | Cleans up and migrates a saved `localStorage` state from an earlier build — drops the old mode field, renames the old classification label, stamps a schema version |
| `narrative-templates.js` | Deterministic prose assembly — every paragraph shared across the Company page, the Narrative brief, the Executive Brief and both generators |
| `reveal-data.js` | Generated. Assigns the normalized object model to `window.REVEAL_DATA` |
| `app.js` | The application. Consumes `window.REVEAL_DATA`; no other input |
| `extract_workbook.py` | Build step. Reads the workbook with openpyxl and writes `reveal-data.js` |
| `test.mjs` | The interface suite. Runs Playwright against the built app and writes `ux-checks.json` |
| `ux-checks.json` | Generated by `test.mjs`, carried into the app by the extractor |
| `validation-report.json` | Extraction, runtime and interface checks, targets, conflicts and counts |
| `assets/crowdstrike-logo.png` | The CrowdStrike wordmark, used small and restrained across the header, the Company and Narrative pages, the Executive Brief, and the printed and branded-preview surfaces |

Rebuild after a workbook change:

```
python3 extract_workbook.py <workbook.xlsx>
node test.mjs                 # writes ux-checks.json
python3 extract_workbook.py <workbook.xlsx>   # carries the interface results back in
```

## Navigation

| Group | Views |
| --- | --- |
| **Explore** | Company · Narrative · Signals · Evidence · Lineage |
| **Research** | KPI Bridges · Sources · Risks & Questions · Rules · Cohorts & Regions · Methodology |
| **Create** | Sunday Signal · Update Email · Audience Translator · Executive Brief |

The Narrative route is a content destination — a full digital research brief — not a mode:
it sits in Explore alongside Company, reachable the same way any other view is, and reading
it changes nothing about how any other view behaves.

Every earlier route still works. `#index` resolves to Company and `#brief` to Narrative, so
old links and bookmarks are not broken. A fixed left-hand rail carries the three groups on
desktop; on a tablet or phone it collapses behind a menu toggle, and the header keeps the
company identity, the research period and global search visible regardless of width.

## The header

Left: the CrowdStrike wordmark, sized to read clearly rather than as a small favicon-scale
mark; there is no separate application-name text beside it. Left of centre: the company and
its ticker. Right: the current research period, a **Last updated** value sourced from the
workbook's own export metadata (or the literal text *Not specified* — nothing is invented),
**Source controls**, global **Search**, and **Create**, which opens a quick menu onto all
four Create destinations. On a narrow viewport the secondary actions collapse behind an
accessible overflow control; the wordmark, the company identity and search stay visible.

There is no mode toggle in the header, no global "Human Review Required" banner, no running
object count, and no source-lane strip in the application chrome — the evidence lanes are
controlled from **Source controls**, not from a banner repeated above every view. Review
status is not a property of the whole application — it is a property of a specific generated
draft, and it is shown there, in that draft's own chrome (see **Human Review Required**
below), never as a persistent warning painted over every view regardless of what is on
screen.

## The Company page

| Section | What it carries |
| --- | --- |
| Hero | Company, ticker, current period, primary signal, the wordmark, one narrative headline, a deck built from the primary-signal object, and five restrained status chips: Current call, Direction, Conviction, Evidence confidence, Current period |
| Key metrics | A seven-tile rail, directly under the heading and above the lead chart; each tile opens its evidence object. On a phone it scrolls horizontally with snap |
| The recovery profile | One lead chart — see below |
| Narrative snapshot | What changed · Why it matters · What remains open, each with a quiet claim-class marker and an *Inspect evidence* action |
| The company story | Three editorial moves, each with a headline, a short narrative, direction, confidence, a small metric comparison, a counterpoint and an evidence count |
| The counterpoint | The decision-relevant counter-evidence as readable prose on a warm ground, not a dense table |
| What to watch next | Three watch items drawn from existing open questions, each with why it matters, what would resolve it and its related signal |
| Research foundation | Object counts, collapsed, at the foot |

The **Current Call** appears as an outlined status chip rather than a red panel. When it
reads Source Needed it carries a *Why Source Needed?* link straight to **OQ-002**. It is a
reviewer-controlled field: no filter, no source control and no interface action moves it.
Human Review Required is deliberately not one of the hero chips — see **Human Review
Required** below for where review status actually lives.

The page spans most of the available content width on a wide screen — the structural
containers (the hero, the lead chart, the editorial bands) follow `--content-max-width`
(1600px) inside an outer `--app-max-width` (1720px), while the running prose inside them is
still capped at a comfortable reading measure via `--prose-max-width` (100ch), so nothing
reads as an uncomfortably long line even though the page around it is wide.

## No object IDs in the default reading paths

Company, Narrative and the Executive Brief are the three default reading paths, and none of
them prints a bare object ID — `EV-…`, `SIG-…`, `OQ-…`, `R-…`, `KPI-…` or a relationship ID
— into running prose, regardless of any toggle. Every citation in that prose is still a real,
clickable control; it just renders as a small, unlabelled mark rather than literal code, and
clicking it still opens the object drawer with the citation's full title as its accessible
name. The literal ID is one click away in the same three places it always was: the object
drawer, **Inspect claims**, Lineage, the Signal or Evidence workspace, Methodology, a
technical-detail disclosure, or an export's own footnotes. Every other view — Evidence,
Signals, KPI Bridges, Lineage, Rules, claim manifests — renders the literal ID exactly as it
always has; only the three reading paths are quiet by design.

## Missing source

Where a fact the reading path would want is not recorded, the default reading paths use a
small structured **Missing source** component in place of a bare "SOURCE NEEDED" label: what
is needed, why it matters, an owner, a priority, a status, and expected evidence, each of
which reads the literal text *Not specified* when the workbook does not supply it — nothing
here is ever invented — plus one-click actions to view the underlying open question, open
lineage, view the expected evidence category, or copy a plain-text research request. The
literal **Source Needed** status still appears exactly where it always has in a technical or
export context — a table cell, a CSV export, a claim manifest — because that is a controlled
status value, not reading-path prose.

## The lead chart

One frame, two series, and a strict rule about what may be drawn.

- **Deployment breadth (Pervasion)** is supplied for all twelve survey periods, so it is
  drawn as a continuous line.
- **Spending intent (Net Score)** is supplied for three of those twelve. It is drawn as
  points, with a connecting segment only where two *consecutive* periods are both supplied.
  The long gap between October 2025 and July 2026 is drawn as a faint dashed rule labelled
  *no intervening periods supplied* — nothing is interpolated, and no line implies data
  that does not exist.
- The current period is highlighted; July 2026 is labelled *historical*.
- Latest values are labelled directly rather than through a legend lookup.
- Every point is hoverable, keyboard-focusable and opens its evidence object.
- The chart carries a `<title>`, a `<desc>` text summary, and a **Show the numbers** toggle
  that reveals the same data as a table with unsupplied periods marked *not supplied*.

## The Narrative view

`#narrative` is a digital research brief, in ten parts: the research question, the short
answer, the signal, what changed, demand and breadth, enterprise and geography, what argues
against it, the signal-to-KPI hypothesis, what to watch, and a methodology note. A sticky
contents bar scrolls to any section. Pull quotes carry the turns in the argument. The
Research Foundation sits at the foot, collapsed. The narrative container follows
`--narrative-max-width` (1480px), wider than a conventional reading column, while its
paragraphs stay capped at `--prose-max-width` for comfortable line length.

The research question is used as the narrative anchor on Company, Narrative, the Executive
Brief and the Sunday Signal, and nowhere else.

## The Executive Brief

`#generator/executive-brief` is a fourth generated output, distinct from the Update Email's
own "Executive note" format (which is still an *email*, addressed to a recipient). The
Executive Brief is a print-ready research brief with no recipient at all: the research
question, a bottom line, the primary signal, what changed, why it matters, the counterpoint,
what to watch, a methodology note, and an optional evidence appendix — assembled from the
same `NARRATIVE` prose and `claim()` manifests as the Company page and the Narrative view,
not a second copy of that logic. Audience and primary-signal selectors let the reading angle
change without changing a fact. Every claim carries a full manifest reachable behind
**Inspect claims**; the brief exports as plain text, Markdown or a self-contained HTML file
carrying the wordmark, and prints as its own named surface. Like the other generators, its
Human Review status lives in its own chrome, not the global header, and no object ID appears
in its body by default.

## Update Email — clean email first

The default view is the email: **To**, **Subject**, and a body of four to six connected
paragraphs with transitions. No labelled compartments. No claim IDs, evidence IDs, rule IDs
or classifications in the body. It is meant to be copied into Outlook after human review.

Four formats: **Clean email** (default) · Structured update · Signal alert · Executive
note. Switching format keeps every selection you have already made.

Five inclusion toggles: **Include logo in HTML version** (on by default, for the downloaded
HTML file only — the copied plain-text body never carries an image) and four content
toggles — methodology footnote, evidence appendix, Human Review line, source IDs — all
**off** by default. The *Generated draft — Human Review Required* line stays on the
generator's own chrome and says so explicitly; it is never part of the copied body and never
a global banner.

## Sunday Signal — one cohesive piece

The default output is a short research essay: a title, a deck, and six to eight connected
paragraphs, with a closing on what to watch. At Standard length it uses at most **three**
visible subheads; at Brief length, none. No heading before every paragraph.

Four composition styles — **Cohesive Signal** (default) · Executive Signal · Data-Led
Signal · Research Note — and three lengths: Brief · Standard · Extended. The lead chart is
optional. **Preview as branded newsletter** presents it on a clean reading canvas carrying
the CrowdStrike wordmark.

## Claim manifests

Every generated paragraph, in every format, still carries a full manifest: claim ID, output
type, rendered text, classification, source evidence IDs, source object IDs, source
worksheets, rule IDs, confidence, caveat, Source Needed fields and generation time.

Manifests are never rendered inline. **Inspect claims** — the one global inspection control
in this application — lightly outlines each paragraph by claim class and opens its manifest
in a panel. Turning it on changes neither the rendered prose nor what a copy or download
produces — a copied email, essay or brief never carries hidden manifest metadata.

## The five claim classes

Every claim in this application carries exactly one of five classifications, and the words
are literal — they appear on screen and in every export exactly as written here:

1. **Client-provided fact**
2. **ETR interpretation**
3. **Hypothesis**
4. **Open question**
5. **Recommended action**

**ETR interpretation** keeps the purple accent it has always carried. A saved draft or
preference from a build that used the firm-branded predecessor of this label is migrated to
it silently, in `storage-migration.js`, the first time this build loads.

## Audience Translator

A three-column split: the audience list on the left, the translated decision narrative in
the centre, and *what stayed fixed* on the right. The centre gives the decision question,
the translation, why it matters to that reader, the best supporting evidence, the
counterpoint and the recommended action, as prose rather than a field-heavy card.

Changing audience never alters a fact, a metric value, a source ID, the signal statement,
the confidence, the current period, the rules or the caveats — the right-hand panel exists
to make that checkable. Three handoffs carry the selected audience into the Sunday Signal,
the Update Email, or the Executive Brief.

## The research views

**Signals** groups the seven readings by the role each plays in the current call — Primary,
Supporting, Watch, Research gap — derived from fields that already exist: the recorded
primary signal, whether current-period evidence is present, and whether the reading itself
is Source Needed. The workbook records no ranking and none is invented. Each row leads with
the name, a one-sentence reading, direction, confidence, current evidence and the principal
caveat; everything else is in the workspace behind it.

**Evidence** defaults to a concise list (statement, period, lane, confidence, related
signal) and expands to cards or a sortable table with CSV export.

**Lineage** keeps the full interactive graph. The proof-case path is the default preset, and
**Tell me this path** renders it as plain language — each sentence uses the relationship
type recorded in the workbook as its verb, so no edge is inferred and no causal claim is
introduced by the retelling.

**Sources** leads with family summary cards — current October exports, historical ETR,
company evidence, external research, analyst layer — over the full register.

**Rules** defaults to *Rules affecting the current narrative*, collected from the claim
manifests the narrative just produced, with *View all rules* for the full registry.

**Risks & Questions** defaults to *Most important now*, ordered by the importance each
question records and then by how many objects it blocks through a recorded BLOCKS
relationship. No proprietary importance score is computed.

## Print

`print.css` is loaded `media="print"` and styles seven named surfaces: Company profile,
Narrative brief, Executive Brief, Sunday Signal, Update Email, Lineage and Evidence
comparison. The Print button opens a menu of those surfaces plus *This page*. Printed
surfaces use the full available page width, and the wordmark keeps its colour on paper.

Print output omits navigation, source controls, drawers, generator controls and hidden
manifests. It keeps the title, the period, the narrative, the visible chart, any selected
footnotes, and — on a generator's own printed draft — its review status. There is no global
"Human Review Required" header warning printed on every surface by default; review status
prints only where that output's own workflow calls for it. Collapsed disclosure panels
print open, so nothing is silently dropped. Print scoping isolates a single view, and the
target is painted before printing, so a surface prints correctly even if it has never been
opened on screen.

## Source discipline

The extracted workbook is the sole factual source. No internet, no model knowledge, no
parametric fill. Nothing about the company is described that the workbook does not record —
there is no headquarters, employee count, revenue figure, product description, industry
label or market-position claim anywhere in this application, because none of those are in
the authorized worksheets. Where a field cannot be supported the default reading paths show
the **Missing source** component described above, rather than a blank or a plausible
substitute; a technical or export context still shows the literal **Source Needed** status
value. Where the substance is unresolved rather than the field, the answer stays in the
narrative and the unresolved item is reachable through a status chip, the Missing source
component, Risks & Questions, the object drawer, or Methodology & Validation — never stacked
into the hero.

October 2026 is the current TSIS period. July 2026 is historical comparison and is never
presented as current. Observations are never interpolated. The Z-Score is deviation context
only: it never creates or changes the Current Call, and the prohibited strength language is
named in the application solely in order to prohibit it.

## Human Review Required

**R-020** makes analyst approval a precondition of external distribution. That status is not
global chrome — there is no persistent top-bar badge, because a review requirement belongs
to a specific draft, not to the whole application. It appears instead: in each generator's
own chrome (Update Email, Sunday Signal, Executive Brief), in a claim's own inspection
metadata, on a generator's printed surface, and in the application's validation status. No
generated output in this application is externally eligible until a reviewer says so.
